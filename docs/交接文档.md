## 三、原版数据怎么采（关键方法论）

### 1. 进副本的正确方式
不是 `cr fb10`，而是 `cr <区域>/<首房间>`：

```
cr kw/damen            关外
cr wf/damen            温府
cr bt/damen            白驼山
cr xd/shankou          血刀门
cr cd/yunmeng/senlin   云梦沼泽
cr xingxiu/xxh6        星宿海
cr mj/shanmen          光明顶
cr huashan/yihua/shandao  移花宫
cr zsd/damen           战神殿
```

### 2. `map <区域>` 是最权威的地图数据
```json
{"type":"map","path":"kw","map":[{"n":"大门坎子","id":"kw/damen","p":[0,0],"exits":["n"]}]}
```
已缓存 25 份：`/tmp/mud/maps/fb10.json … fb34.json`

> ⚠ **id 不可靠**，实测到处是同一个 id 复用多个节点：
> - 华山论剑：5 个峰全叫 `top`
> - 桃花岛：10 个节点全叫 `haitan`
> - 云梦：`huozhao3` 复用 3 次（洪荒古泽/围墙/茅屋）
> - 关外：`瀑布下/大清龙脉` 都叫 `xiaotianchi`
>
> ⚠ **地方名也可能和真实路径不一致**：
> - 围墙真实路径是 `cd/yunmeng/weiqiang`
> - 邀月宫真实路径是 `huashan/yihua/yaoyuegong`（map 写 `yaoyue`）
> - 北厢房真实路径是 `mj/beixiang`（map 写 `bexiang`）
>
> 所以**判断房间是否存在，必须靠实走**，不能只靠 map 的 id。

### 3. 走图脚本（`/tmp/mud/walk.js`）
```bash
node walk.js <入口> "go south,go north,..." <输出json>
```
- 走不动会自动 `kill <NPC实例id>` 再试（**kill 必须用实例 id，不能用名字**）
- `look` 不返回任何包，房间 NPC 列表只随移动/进副本的包下发
- 移动成功后 room 包里的 `exits` 才是真出口

### 4. 界面按钮对应的真实命令
动作栏按钮发的**不是中文**：

| 界面按钮 | 实际命令 | 证据 |
|---|---|---|
| 点火 | `fire` | `fire → 你点燃了火折，发现密道中似乎有一条路可以走过去。`（`点火`/`dianhuo` 都是"什么？"） |

### 5. 踩过的坑
- **背包满**：日志提示"你身上东西太多了。"，掉落捡不到（宫女掉火折子 95.5% 也拿不到）
- 战斗状态下移动无效，先清怪
- 有的出口是**动作之后动态出现**的（如密道 `fire` 后才出现 `west`、云梦砍芦苇后才出现 `north`）

## 九、常见坑（写脚本时注意）

1. **不要用 python 字符串替换改 JS**，很容易把 `})().catch(...)` 尾巴插重复 → 语法错误。要改就整文件重写。
2. `kill` 只认 NPC **实例 id**，`kill 名字` 回"你要攻击谁？"
3. `look` 单独发不返回任何东西，拿房间信息必须靠移动
4. 移动响应里可能同时带战斗文本，解析 `"path":"` 即可
5. 房间文件删除后，要清理其它文件里指向它的 exit（否则 `check_map_layout` 报悬空）
6. 测试服必须用 rsync 同步（含删除），否则会跑旧代码
7. 服务器重启后要等 40~70 秒再测
