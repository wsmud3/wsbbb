# 外部 BUG_REPORT 交叉核对与本轮修复

核对基线：外部报告注明的 `28626aa035fad8d0b47b1c4be4a3302ca35952a7`，以及本轮待发布工作树。报告不是线上事故证据；下面区分源码确认、离线复现和需要玩法审批的判断。用户已批准将新增安全与崩溃问题并入本轮。

## 主要结论

- 有效补充：聊天转义被覆盖、后台文件路径边界、旧存档装备分组缺失、组队回包空指针、襄阳疏散死循环、NPC 克隆共享数据、回血调试写盘等确实漏在前一轮专项验收之外，现已补修。
- 重合：管理员门槛、可伪造旧凭证、密码恢复、手机号查询、CORS、WebSocket 拆包/分片、心跳对象移除导致跳过、保存失败隔离等，与 Astra/Luna 清单重合。
- 不能照单执行：拍卖行服务端主动关闭；NPC/玩家系数、跨服重名、军功奖励、进阶退款需要确认规则；襄阳任务原报告提供的条件修改方向不对。
- 旧报告称真意/山外山“无实锤”不能作为通过结论。本轮对奖励写入 SQLite 后、共享领取记录写入前直接结束子进程，复现并验证了持久化边界；此前也有真意命中阶段、一次性上下文、自创叠层等已确认问题。

## 报告还遗漏或未充分说明的点

1. 后台 readBody 把业务回调异常当 JSON 解析异常，再调一次回调；本轮将解析/执行分离，并限制请求体长度。
2. 更换密码后的权限撤销必须覆盖 WS 重连，不只是 HTTP 管理接口；本轮共用验证器。
3. 登录重连条件有双重否定错误、切角色会关闭准备复用的 socket；本轮修正，并避免半加载角色进入在线保存列表。
4. 山外山旧 pending.inFlight 可在重启后永久阻止补发；现在角色背包和永久领取凭据同一 SQL 写入，旧共享领取记录继续识别，旧运行中标记不再作为锁。
5. 保存失败不能只打印日志：本轮保存失败快照、关服返回失败、世界主备档均损坏时拒绝空档启动。
6. 发布“端口开着”不能证明新进程已更新：本轮进程启动时捕获 SHA，逐一核验 web/100/200 的服务与版本，再更新 deployed_ref；失败不覆盖线上数据库。
7. “SQL 全程参数化”表述过满：getUser/getUsers 等仍接受内部 SQL 条件片段。当前已检查的公开入口使用固定字段和参数，未复现这条路径的外部 SQL 注入；既不宣称全仓无注入，也不把字符串拼接自动等同漏洞。
8. 原报告的 node --check 特例应以实际加载器 sanitizeScript+compileFunction 检查，不应把任意语法错误都用同一理由豁免。

## 验证边界

本地合成数据、VM 行为探针、真实 SQLite 子进程退出/重开、真实 HTTP/WS 连接和生产构建；没有连接生产数据库、修改真实角色或运行线上漏洞利用。Windows 本地通过不等于 Linux PM2/cron、APK、正式服高并发和所有副本流程均已验收。性能优化不报告未测量的提速百分比。
